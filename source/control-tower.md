## C 目标产品结构没变 {span=2}
```flow TB
老板 -> *数字员工: 一句话交办
*数字员工 -> Responsibility: 长期职责
*数字员工 -> Work: 本次工作
Responsibility -> Work: 时间 / 事件 / 手动触发
Work -> Agent Runtime: 自由执行
Agent Runtime -> Skills / Tools: 取数 / Browser / Office / 通知
Skills / Tools -> 外部系统: 美团 / 抖音 / 钉钉
Work -> *Outcome: 真实业务结果
*Outcome -> Artifact: Excel / PPT / 预览
*数字员工 -> Memory: 门店 / 口径 / 模板 / 偏好
*数字员工 -> Connection: 账号 / 授权范围
```

**可替换的是 Runtime、Browser、Office、模型、Temporal；不能漂的是 Employee、职责、权限、记忆和结果。**

## G 判断一次进展到底算不算“真进展” {span=2}
```flow LR
代码候选 -> 单项验证
单项验证 -> 生产发布
生产发布 -> 真实E2E
真实E2E -> *客户Outcome
```

| 层级 | 老板看板怎么记 |
| --- | --- |
| 代码候选 | 不涨或只小幅涨 |
| 单项能力证明 | 可以涨，但标“待串” |
| 生产发布 | 只有解除关键节点才明显涨 |
| 真实 E2E 跨节点 | **明显涨** |
| 客户 Outcome | **完成节点** |

所以今天 12:44 的上下文压缩候选不会让我写“首单快完成了”；只有它在生产让一句话稳定进入执行，首单才会从当前节点向右移动。
