## B 用户真正应该经历什么 {span=2}
```flow LR
(老板进入工作台) -> 团队首页: 看谁在工作
团队首页 -> *小账: 经营报表员工
*小账 -> 对话: “上个月经营怎么样？”
对话 -> 工作: 员工自己取数并显示安全进度
工作 -> 成果: 真实来源 + 原模板 + 可下载
成果 -> 对话: “这里改一下，以后都按这个格式”
对话 -> 长期职责: “每月10号10点发给我”
长期职责 -> (下次自动交付): 同一员工继续负责
```

目标体验只有一个：老板记住“找小账”，不用记住 Task、Run、Capability、模板版本或数据采集步骤。

## D 用户故事：我想安排每周报告 {span=2}
![生产真实截图：报表员工已上岗，但无法确认自己能承担哪些具体工作。](assets/product-owner-walkthrough-20261010/pub-02-conversation.png)

**用户说：** “我想安排定时工作，请先告诉我当前支持的安排方式。”

**生产复验：** #792已生效，员工现在会用业务语言说明可读取已授权门店经营数据并整理经营报告；这一P0已关闭。历史截图保留为修复前证据。

```flow LR
已上岗/空闲 -> {员工能说明自己的职责吗？}
{员工能说明自己的职责吗？} -> no 暂不可用/待配置: 状态要诚实
{员工能说明自己的职责吗？} -> yes 给业务例子: 日报 / 周报 / 月报 / 临时分析
给业务例子 -> 用户自然交办
用户自然交办 -> 形成职责与排期
```

**我的判断：P0。** 一个“已上岗”的员工必须准确知道自己当前会什么、能访问什么、哪些工作可以定时。否则所有后续页面优化都救不了信任。

## E 用户故事：我只想看哪些事需要我 {span=2}
![生产真实截图：任务与计划中出现大量工程诊断历史，并被计入“等待我回复”。](assets/product-owner-walkthrough-20261010/pub-03-plans.png)

历史生产曾显示 **“等待我回复的工作（12）”**。#791生产复验后客户侧已归零；历史截图保留为修复前证据。版本页仍BUSY，说明“客户投影干净”和“版本生命周期没有未完成工作”是两件事，后者仍需安全收口。

| 用户看到的对象 | 应该出现 | 当前判断 |
| --- | --- | --- |
| 真正需要老板补资料或做决定 | 是 | ok |
| 待批准的高风险业务动作 | 是 | ok |
| 员工正在做的业务工作 | 在“正在做”中展示 | warn |
| 工程诊断 / provider probe | 只在运营诊断 | no |
| 历史测试 Work | 不占用“需要你” | no |

这不是文案问题，而是 **customer Work projection 的边界错误**。更严重的是，同一批 WAITING_FOR_USER 还让生产版本页进入 BUSY，直接阻塞员工升级。#791 已给出客户投影最小修复；Control 4.2 进一步规定内部工程 Work 不能长期占用客户生命周期，历史状态必须走证据化 safe-close。
