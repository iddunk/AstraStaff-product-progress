## B 老板最终应该经历的完整旅程 {span=2}
```flow LR
团队首页: ✅ -> 找小账: ✅
找小账 -> *一句话交办: 🟡 当前
*一句话交办 -> 看工作进度: ⚪
看工作进度 -> 下载真实月报: 🔵 能力待串
下载真实月报 -> “这里改一下”: ⚪
“这里改一下” -> 第二版成果: ⚪
第二版成果 -> “以后都这样”: ⚪
“以后都这样” -> 下月自动交付: ⚪
```

**产品不应该让老板知道：** Capability、Run、Task、评测编号、镜像 SHA、迁移号。

**当前体验节点：** 员工启动上下文正在收口。目标不是“返回系统说明”，而是用户说完后直接看到：**正在处理哪个月份 → 正在取数 → 正在生成。**

## G 下一次你验收报表员工，只看这 5 步 {span=2}
| 步骤 | 用户动作 | 通过标准 | 当前 |
| --- | --- | --- | --- |
| **1** | “上个月经营怎么样？” | 直接开始工作 | 🟡 当前 |
| **2** | 等待 | 看见业务进度，不看工具噪音 | ⚪ |
| **3** | 点成果 | 真实来源 + 原模板 + 可下载 | 🔵 能力待串 |
| **4** | “这里改一下” | 同一对话出第二版 | ⚪ |
| **5** | “以后都按这个格式” | 下次自动复用 | 🟡 局部能力已有 |

```flow LR
1 一句话 -> 2 进度
2 进度 -> 3 下载
3 下载 -> 4 修改
4 修改 -> 5 记住
```

**这 5 步全绿，报表员工才算真正“好用”。**

## H 现在共同定调的只有 3 个体验点 {span=2}
```callout ok 你不回复也不会阻塞研发；这里只放值得 Owner 定调的产品问题
```

### 1. 员工卡片优先展示“最近成果”
推荐：**接受。** 比“空闲”更能建立信任。

### 2. 工作中的进度只讲业务阶段
推荐：**正在取数 → 正在生成 → 正在校验 → 已交付**。不要向客户播放内部 Tool 调用流水账。

### 3. 成果卡片把来源可信度说成人话
推荐：显示 **数据来源、覆盖月份、缺失项**；不要显示 evidence id / checksum。

**已经确认、不再重复问：**
- 首次没有成果时，给 3 个真实可交办例子。
- 默认上岗取消人工审核；特殊高风险能力未来再补例外。
