PRODUCT DECISIONS

四个不能走偏的产品决定

Owner 待确认

01 / 卖“结果”，不卖“内部实现”

消费者看到应用能办什么、需要哪些材料、花多少钱、成功样例；看不到 Hermes、MCP、Employee Deployment 或租户概念。

02 / 先自营，后开放生态

首期运营训练并发行标准化 Skill，不做第三方开发者入驻、复杂分账、任意脚本执行，先把一个付费结果跑通。

03 / 对话是工作台，Skill UI 按需生长

能一句话触发，也能从专用输入卡片开始。缺素材时逐步补齐；确认过的偏好复用，不强迫每次重填。

04 / 完成必须有证据

生成、交付、失败、退还额度分别有状态和凭据。平台保留工作过程、成果和计费事实，不用“已完成”遮盖失败。

两个需要特别设计的异常路径

权限 / 资料缺失

缺资料不直接失败：通过步骤式 Skill UI 提醒并收集；用户首次确认的规则可以复用，后续变化再确认。Tool 不可用时应说明受限能力，不能偷偷模拟成功。

付款成功但工作失败

支付和工作不是一个原子事务。先确认支付回调并发放权益；执行前预留额度，成功结算，失败解除预留或补偿。所有动作幂等，账面可见。

0. 目标与非目标

产品目标：让第一个数字员工从发现、试用、购买，到真正交付可复用成果，形成能收费、能复制的业务闭环。MVP 样板：商品上新文案。首期仅平台自营，不做第三方开发者入驻、复杂分账或第二套 Agent Runtime。继续复用 Astra V3 Employee / Conversation / Work Journal / Artifact / Permission / Connection / Ontology，Runtime / Browser / Office 作为 Port。

2. Agent / Skill / Tool / 商品分工

Agent / Employee理解目的、补齐输入、选择能力、组织连续工作、归档结果。
Skill / ToolSkill 描述一类工作方式；Tool 提供可授权的领域动作。不要为每个按钮编写固定业务链。
App / Listing消费者入口与商业条款：展示、权益、定价、限制、售后。不是第二套 Agent 真相。

3. 权限、成本与对账

消费级权限与隐私

  • 匿名可看样例，登录或支付只在必要节点发生。
  • 用户私有对话/文件/Artifact 按身份隔离；运营仅看最小必要审计数据。
  • 外部平台动作需显式授权；READ/DRAFT 与真实发布/回复动作隔离。
  • 禁止导入 Hermes 本地密钥、记忆与任意可执行文件。

商业计费

  • 用户售价和模型供应商成本独立记录；价格版本绑定订单。
  • 上游 Base URL/API key 可切换，历史订单不跟着改价。
  • 记录模型/输入输出/缓存/工具调用等成本与业务额度结算。
  • 月度与上游线下对账即可，MVP 不开发逐笔供应商适配。

5. 明确排除项

首期不做

第三方开发者平台、Skill 自由上传执行、平台分账、复杂流程画布、消费者自建运行时容器、支付渠道大而全、统一第三方供应商对账 API。

上线不可省略

业务成功证据、正确的支付回调与权益、真实成果交付、可靠退款/退额度、租户和用户隔离、可回滚、异常提示、移动端主路径体验。
